# G1

THIS TASK ONLY. Two interpreter runs can drive one drone and mutate the same PlayerData.

Evidence in src/server/Services/ScriptService.luau: `startRun` cancels the previous run, waits PREVIOUS_RUN_WAIT = 3s, then starts anyway. `set_speed(0.5)` + limp move = 3.2s > 3s. `simulate()` can run ~50s of real time inside the live interpreter. After 3s a second LiveWorld starts. Economy is not re-entrant → dupe/teleport.

Fix:

1. Store `run.thread` from task.spawn.
2. On Stop / new Run / leave: cancelled = true, then `task.cancel` the thread.
3. Hard mutex: never start a new run until `previous.finished == true`. No 3s timeout. If you timeout, task.cancel first, wait until finished, then start.
4. LiveWorld.wait: slice task.wait to ~0.1s, check shouldStop every slice.
5. SimWorld.wait: yield at least every virtual second.

Add a test: start a long simulate(), immediately RunScript again. Assert one run, cargo did not double.

Do not retune economy, tutorial, or crops. Verify: `lune run tests/run`.
